2️⃣ Minimal DB migration (Postgres)

Because you don’t have a migrations directory in this repo, you can run this once against your Postgres (via psql, Replit DB console, or a one-off script):

ALTER TABLE bonds
  ADD COLUMN IF NOT EXISTS bond_score integer;

ALTER TABLE bonds
  ADD COLUMN IF NOT EXISTS risk_tier varchar(20);

-- Optional: soft constraints if you want
-- (you can skip this if you prefer no DB-level checks)
ALTER TABLE bonds
  ADD CONSTRAINT bond_score_range
  CHECK (bond_score IS NULL OR (bond_score >= 0 AND bond_score <= 100));


After this, the Drizzle schema and actual DB match.

If you prefer to do this via TS instead of direct SQL, you could also add a tiny one-off script that runs db.execute(sqlALTER TABLE ...), but the SQL above is the essence.

3️⃣ API wiring – /api/bonds create & update

The good news: your routes are already almost good to go.

In server/routes.ts we saw:

// Create new bond
app.post("/api/bonds", authMiddleware, async (req: AuthRequest, res) => {
  try {
    const validation = insertBondSchema.safeParse({
      ...req.body,
      ownerId: req.user!.id,
    });

    if (!validation.success) {
      return res.status(400).json({ 
        error: "Invalid input", 
        details: validation.error 
      });
    }

    const bond = await storage.createBond(validation.data);
    res.json(bond);
  } catch (error) {
    console.error("Create bond error:", error);
    res.status(500).json({ error: "Failed to create bond" });
  }
});


Because we extended insertBondSchema, any bondScore + riskTier fields you send from the frontend will now:

be validated,

pass through to storage.createBond,

and be stored in the bonds table.

The update route is already generic:

// Update bond
app.patch("/api/bonds/:id", authMiddleware, async (req: AuthRequest, res) => {
  try {
    const bondId = parseInt(req.params.id);
    const bond = await storage.getBond(bondId);

    if (!bond) {
      return res.status(404).json({ error: "Bond not found" });
    }

    // Verify ownership (admin bypass)
    if (bond.ownerId !== req.user!.id && req.user!.role !== "admin") {
      return res.status(403).json({ error: "Forbidden" });
    }

    const updated = await storage.updateBond(bondId, req.body);
    res.json(updated);
  } catch (error) {
    console.error("Update bond error:", error);
    res.status(500).json({ error: "Failed to update bond" });
  }
});


So as soon as the DB has the columns, any PATCH like:

{
  "bondScore": 82,
  "riskTier": "low"
}


will update those fields on that bond.

No further change is required on the backend storage layer, because:

async createBond(bond: InsertBond): Promise<Bond> {
  const [created] = await db.insert(bonds).values(bond).returning();
  return created;
}

async updateBond(id: number, data: Partial<InsertBond>): Promise<Bond> {
  const [updated] = await db
    .update(bonds)
    .set({ ...data, updatedAt: new Date() })
    .where(eq(bonds.id, id))
    .returning();
  return updated;
}


already spreads whatever bondScore/riskTier you give it.
